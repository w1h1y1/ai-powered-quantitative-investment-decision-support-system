# AI Quantitative Investment Decision Support System

## Checkpoint 4 – User Evaluation Task Sheet

### Introduction

Thank you for taking part in this user evaluation.

This study evaluates an **AI Quantitative Investment Decision Support System**
designed to support users in exploring financial market data, technical
indicators, quantitative trading strategies, portfolio information and
AI-generated market analysis.

The purpose of this evaluation is to assess:

* whether the main system functions work as expected from a user's perspective;
* whether the system is easy to navigate;
* whether quantitative information is presented clearly;
* whether the AI-generated analysis is understandable and useful;
* whether the overall system provides useful investment decision support.

This system is designed for **educational and decision-support purposes only**.
Transactions created within the application are simulated and do not involve
real money.

### Estimated Completion Time

Approximately **15 minutes**.

### Instructions

Please complete the tasks in order.

If you are unable to complete a task, **do not worry and do not spend excessive
time trying to solve it**. Make a note of the problem and continue to the next
task where possible.

Please also make a note of anything that:

* is difficult to understand;
* is difficult to find;
* does not behave as expected;
* is particularly useful;
* could be improved.

After completing the tasks, please complete the accompanying Microsoft Forms
questionnaire.

# Task 1 – Register a New Account

1. Open the AI Quantitative Investment Decision Support System.
2. Locate the **Register** function (on the Sign in page, switch to
   "Need an account?" → **Create one**).
3. Create a new test account using valid registration information
   (username, email, password, confirm password).
4. Submit the registration form.
5. Confirm that the registration process completes successfully.

> Tip: the password must be at least 8 characters and must not be entirely
> numbers. If the password is rejected, the form shows the reason.

### Goal

Evaluate whether a new user can independently identify and complete the
account registration process.

### Completion

* [ ] My account was successfully created.
* [ ] The registration process was clear.

# Task 8 – Run a Strategy Backtest

1. Navigate to the **Strategy Backtest** section (left-side menu).
2. Select AAPL as the asset.
3. Review the strategy and available parameters.
4. Run the backtest.
5. Locate the following results:

   * **Total Return**;
   * **Maximum Drawdown**;
   * **Executed Orders** (number of trades);
   * **Swing Win Rate** (percentage of profitable swing cycles).
6. Examine at least one backtest chart (equity curve, drawdown, exposure, or
   price/signal chart).

> Note for participants: if a run produces no trades, the win rate may be 0%
> or N/A. That is a normal outcome for some parameter combinations.

### Goal

Evaluate whether users can successfully run and interpret a quantitative
strategy backtest.

### Completion

* [ ] I successfully ran the backtest.
* [ ] I found Total Return.
* [ ] I found Maximum Drawdown.
* [ ] I found the number of trades (Executed Orders).
* [ ] I found Win Rate (Swing Win Rate).
* [ ] I understood the general purpose of the backtest results.

### Evaluation account preparation

* Each participant registers their own account (data isolation is enforced and
  automated-tested); alternatively pre-created accounts can be provided.
* Portfolio liquidity starts at $0.00 until an Initial Deposit is recorded —
  Task 10 includes the deposit step; observers should verify the participant
  finds the Funding panel without facilitator help (that is part of the
  usability evidence).
* AAPL/XOM/JPM/QQQ are searchable from any account (securities are shared and
  remote-resolvable); a one-time `seed_securities` run makes AAPL/SPY/QQQ/MSFT/
  AMZN immediately available.
* Registration passwords are enforced by Django validators (minimum 8
  characters, not all-numeric). The form shows the reason on rejection but
  does not display the requirements upfront — record any participant confusion
  as a usability finding.
* AI Insights requires the DeepSeek key configured on the backend; if the key
  is unavailable during a session, record it as an external-dependency
  observation rather than a system defect (the UI shows an explicit
  "unavailable" state by design).
